Second Brain. A personal project, 2026

One place for everything I save, kept on my own laptop.

Second Brain is a personal notebook app I designed and built with Claude Code. I send it a message or a photo, and it works out what is inside, suggests where each piece belongs, and saves it as a plain file I own. Each section is designed around the kind of thing it holds, which is why I have drawn it here as a house. Choose any room to see that part of the app.

The front end is React and TypeScript. A Python server keeps a SQLite search index, and every note is a plain Markdown file tracked in git.

Today

Everything starts with a message.

I can send a grocery run, concert tickets, and a to-do in one message. The app splits it into separate items and shows where it would file each one. Nothing is saved until I press File, so I can fix anything it got wrong first.

Coming up collects what is due soon from across my notes, so expiring food and this week's show sit in one list.

Try sending one

In this demo, simple rules in your browser stand in for the model that sorts messages on my laptop. The six samples and anything you type go through the same rules.

Kitchen

It keeps track of what is in my fridge and when it goes bad.

I tell it what I bought, and it sets a use-by date and puts it on Today three days before it goes bad. I drew the kitchen as an actual fridge, freezer, and pantry, because knowing where something is helps as much as knowing when it expires.

The grocery list learns what I usually buy and suggests it.

Coffee

A log of every bag of coffee, to learn what I actually like.

The roast, origin, and process come straight off a photo of the bag's label. Each bag gets a freshness curve, so I can see when the beans are at their best.

Over time it shows patterns in what I liked, such as light roasts from Ethiopia grown above 2,000 m.

Records

Each record gets its own page, in the color of its vinyl.

The page holds the track list, where I bought it, and why I keep it. Colored vinyl tints the whole page, and black records keep the room dark. Each record is recognizable at a glance, the way it is on the shelf.

It also remembers the records I have let go and the ones I am still looking for.

Events

Concert tickets live in a wallet, the way they do on a phone.

Each pass keeps the venue, seats, what I paid, and when I bought it. Upcoming shows land on the calendar automatically, and past ones stay, so I can look back at everything I have seen.

The price and purchase date stay saved long after the ticket email is gone.

Classes

My class notes, organized by topic across every course.

Two courses that teach the same idea get merged into one chapter, with each point linked back to the slide it came from. Anything Claude adds or disagrees with is clearly labeled, so I always know what came from my lecturers.

Review questions come back on a schedule, timed for just before I would forget them.

How sorting works

Sorting runs entirely on my laptop.

Fixed rules handle what a small AI model tends to get wrong, like dates, names, prices, and ticket counts, so it does not guess them. The model, Qwen3-VL 4B, handles the rest, and Apple's Vision reads the text in screenshots. I had Claude write down how it reads messages. I turned that into rules and a step-by-step prompt, so the model reads messages the same way. All of it runs locally, so my notes never leave the laptop to be sorted.

Claude Code worked in a sandbox that let it write only to the project folder, and it asked me before doing anything else.

The files

Every note is a plain text file I own.

Each item is saved as its own Markdown file and tracked in git. The app's search, calendar, and map are all built from these files, so if the app ever went away, every note would still open in any text editor.

Bulk changes to my real notes need a preview that changes nothing, my approval, and a backup first. The app never deletes a note, and git keeps every version.

Overnight

Overnight, Claude Code turns my class notes into study pages.

One agent drafts a topic page from my class notes. A second agent checks every claim against the page it cites and sends back anything that does not hold up. I review the drafts in the morning.

A privacy scan runs before anything is published.

      What I learned

      Make adding things effortless. Sending a quick message was already a habit, so it became the main way in. Every note still has a page to edit, but editing comes second.

      Design each section around what it holds. Generic forms kept feeling like work. A fridge, a wallet, and a record sleeve make each section obvious at a glance.

      Keep the data in a format that outlives the app. Plain Markdown files in git open in any text editor. The database is only an index, and it can be rebuilt from the files at any time.

      Make Claude's work easy to check. Every point on a class page links to its slide, anything Claude added is labeled, and a second agent reviews each draft. Nothing the app sorts is saved until I approve it.

      Give AI a plan, checkpoints, and guardrails. I plan in one chat and build in another. Claude Code works from written plans, stops at checkpoints with clear options for me to pick from, and works in a sandbox that writes only to the project folder and asks me before anything else. A guard blocks every delete command, and anything Claude Code removes waits in a trash folder for 7 days, so it can work safely next to my real notes.

      Treat AI usage as a budget. I log what each task costs, run a small test before any large job, and schedule the heaviest work overnight. Drafting a class page now has a known cost, so a big job starts with an estimate.
